Section 01

What is SYLESS?

SYLESS is a full-stack, AI-powered, browser-based programming IDE that lets users write code in plain English sentences. Instead of learning complex syntax like Python or JavaScript, beginners write naturally worded statements that are compiled into real Python code and executed live inside the browser.

Core Idea: Write English → SYLESS compiler converts it to Python → Python runs on the server → Output appears in the browser terminal — all in under a second.

A Simple Example

SYLESS Code (what the user writes)

SYLESSmake name = "Alice"
make age = 25
say "Hello {name}, you are {age}!"
check age >= 18 {
    say "You are an adult"
}
otherwise {
    say "You are a minor"
}

Generated Python (auto-compiled)

PYTHONname = "Alice"
age = 25
print(f"Hello {name}, you are {age}!")
if (age >= 18):
    print("You are an adult")
else:
    print("You are a minor")

The user never sees the Python. They just see their output. The entire compilation happens transparently.

Section 06

Phase 1: Lexer — Turning Text into Tokens

The Lexer (also called a tokenizer or scanner) reads the raw SYLESS source code character-by-character and groups characters into meaningful units called tokens.

Analogy: Like reading a sentence word-by-word. The lexer splits say "hello" into: [SAY] ["hello"]. It doesn't understand grammar yet — it just identifies the individual "words" of the language.

Other Token Categories

  • Literals: NUMBER, STRING, BOOLEAN
  • Operators: +, -, *, /, %, **, ==, !=, <, >, <=, >=
  • Assignment: =, +=, -=, *=, /=
  • Delimiters: { } ( ) [ ] , . :
  • Arrow: -> (used in say -> "text")
  • Identifiers: variable/function names
  • Comments: lines starting with #
  • Special: NEWLINE, EOF

Lexer in Action

INPUT → TOKENSInput:  make age = 25

Output tokens:
[MAKE, "make"]   [IDENTIFIER, "age"]   [ASSIGN, "="]   [NUMBER, 25]   [EOF]


Input:  check x > 5 { say "big" }

Output tokens:
[CHECK] [IDENTIFIER, "x"] [GT, ">"] [NUMBER, 5] [LBRACE] [SAY] [STRING, "big"] [RBRACE]
Smart Feature: The lexer detects template strings (strings containing {variable}) and marks them with isTemplate = true so the generator can emit Python f-strings.
Section 07

Phase 2: Parser — Building the AST

The Parser takes the flat list of tokens from the Lexer and builds an Abstract Syntax Tree (AST) — a hierarchical tree structure that represents the logical meaning of the code.

Analogy: If the Lexer reads individual words, the Parser understands grammar. It knows that check must be followed by a condition and a block { }. The AST is like a diagram of how the sentences are structured.

Section 09

Python Execution — Sandboxed & Secure

After code generation, the Python source code is executed securely on the server. This is one of the most technically critical parts of SYLESS — running user-submitted code safely without exposing the server.

Security Risk: If a user writes import os; os.system("rm -rf /") and it runs on the server — catastrophic. SYLESS has multiple layers to prevent this.

Security Layer 1 — Static Code Analysis

Before execution, the generated Python is scanned with regex patterns that block dangerous operations:

BLOCKED PATTERNS (executor.js)// Automatically rejected before Python even starts:
BLOCKED_PATTERNS = [
  /import\s+os/,         // no filesystem access
  /import\s+subprocess/,  // no spawning child processes
  /import\s+sys/,        // no system manipulation
  /open\s*\(/,           // no file reading/writing
  /exec\s*\(/,           // no dynamic code execution
  /eval\s*\(/,           // no eval
  /globals\s*\(\s*\)/,  // no globals() introspection
  /getattr\s*\(/,       // no dynamic attribute access
]

Security Layer 2 — Restricted Builtins Sandbox

A Python "sandbox prefix" is injected before every program that restricts which built-in functions are available:

SANDBOX PREFIX (prepended to every execution)# Only these safe built-ins are exposed to user code:
_safe_builtins = {
    'print': print,  'range': range,  'len': len,
    'int': int,  'float': float,  'str': str,
    'list': list,  'dict': dict,  'set': set,
    'abs': abs,  'max': max,  'min': min,
    'sorted': sorted,  'enumerate': enumerate,
    # ... ~25 total safe functions. No os, no sys, no file I/O.
}

Security Layer 3 — Process Isolation

The code runs in a completely separate child process (not in the main Node.js server process), with strict resource limits:

The Big Technical Achievement

Most "learn to code" platforms wrap existing languages with tutorials. SYLESS built an entirely new programming language from scratch — with its own tokenizer, grammar, AST, and code generator — that compiles to Python. This is the same fundamental architecture used by real languages like TypeScript (compiles to JS), Kotlin (compiles to JVM bytecode), and CoffeeScript (compiles to JS).

The difference is SYLESS chose Python as the compilation target because Python has the richest ecosystem of libraries (NumPy, scikit-learn, etc.), making SYLESS programs capable of serious computation despite looking like English.

How a Single Run Request Flows Through the Entire System

  • 1
    User types SYLESS code in the Monaco editor and clicks "Run" The React frontend sends a POST request to /api/compile/run with the code as JSON.
  • 2
    Express rate limiter checks the IP Maximum 30 compile requests per minute. If exceeded, returns a friendly error.
  • 3
    Compiler Phase 1: Lexer scans the source Converts raw text into a flat list of typed tokens (SAY, IDENTIFIER, NUMBER, etc.).
  • 4
    Compiler Phase 2: Parser builds the AST Groups tokens into a tree of nodes (IfStmt, FuncDef, Print, etc.) following SYLESS grammar rules.
  • 5
    Compiler Phase 3: Generator emits Python Walks the AST and produces valid Python 3 source code with correct indentation.
  • 6
    Security check on generated Python Regex patterns scan for import os, eval(), open(), etc. Blocked if detected.
  • 7
    Python written to a temp file and executed as a child process The sandbox prefix is prepended. A 10-second timeout is applied. Output is capped at 100 KB.
  • 8
    Temp file deleted immediately after execution The Node.js backend reads stdout/stderr from the completed process.
  • 9
    Python errors translated to user-friendly messages NameError → "did you use 'make' to create it?", ZeroDivisionError → "check your math!", etc.
  • 10
    JSON response returned to frontend { output, error, executionTime, pythonCode, tokens, ast } — displayed in the terminal panel.
